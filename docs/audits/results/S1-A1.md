## 1. Executive summary

S1 is built the right way round: the "Grade 10 marks never say Qualify now" rule lives in one
place (`marksBasis` → `shownVerdict` in `packages/admissions`), so every screen, tool and re-check
inherits it; the report kinds are one list (`REPORT_KINDS`) held to the database CHECK by a test;
the grade is stored as given plus the date given and computed on read (`currentGrade`, SAST year,
capped at 12), with a database constraint that a grade always has its date; `subjectDoors` says
"can't check" rather than "all open" on an empty catalogue; and the A5-09 fix counts wrong PINs
per number under an advisory lock with the number only as an HMAC. The red team passes 100%.

The weaknesses are at the **edges of those rules**: one reader of "the latest report"
(`examInputs`, which decides which papers the learner is protected during) was not moved to the
new Grade-10-last order (A1-34); the rule that a Grade 10 report is labelled as one depends on a
picker whose default flips to "Final Grade 11 report" on 1 January, exactly when Grade 10 final
reports are uploaded, while the extracted grade and the learner's own grade are never cross-checked
(A1-35); and the wrong-PIN cap is a hard 24-hour lockout that anyone who knows a number can trigger
with four PIN requests (A1-36).

**Top 5 risks**

1. **A1-34** A matric learner who adds their old Grade 10 report has their exam papers (and the
   "never during a paper" hold) worked out from Grade 10 subjects.
2. **A1-35** From 1 January, a Grade 10 final report defaults to "Final Grade 11 report" and is
   scored as Qualify now / Plan B; nothing on the server notices.
3. **A1-36** Any caller who knows a learner's number can stop them signing in on a new device for
   24 hours, renewably, for four SMS a day.
4. **A1-41** In production today (0 verified programmes) a Grade 10 learner's home says "0 courses
   you're on track for" beside a Subjects card that correctly says it can't check.
5. **A1-37** A number past the wrong-PIN cap still gets PINs by SMS that can never work, and is
   told to "wait a few minutes".

## 7. What's genuinely good

- **One rule, one place.** `marksBasis`/`shownVerdict` turn "qualifies" into "on track" inside `packages/admissions`, so the results page, home, goal card, What I need, re-checks and every agent tool got the rule without each re-implementing it; the widened `ResultVerdict` type carries `on-track` to every label map (content's verdict maps gained the key).
- **The grade is derived, not stored stale.** Grade plus date given, computed on read in SAST, capped at 12, with `check ((grade is null) = (grade_given_on is null))` in the database and the January check only while a school grade remains.
- **Report kinds are one list** used by the CHECK (0024), both pickers, the API's zod enum and the content keys, with a test that saves every kind and refuses an unknown one.
- **`subjectDoors` refuses to reassure**: no courses or no subjects → `unknown`, never "every door is open", and the web page needs no JavaScript (`details`).
- **A5-09 is done carefully**: the wrong-PIN count is HMAC-keyed (rule 4, tested), taken under an advisory lock in the same transaction as the insert, recorded even though the sign-in fails (gotcha 8 respected), and the store-review path keeps its own window budget.
- **The agent's context states the grade** and, at Grade 10, that applications are two years away, and the prompt routes subject-choice questions to code (My subjects) rather than the model's memory; the red team still passes 100%.
