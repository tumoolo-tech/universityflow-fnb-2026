## 1. Executive summary

The production paths built this session are careful:

- **Read aloud can't carry learner data.** The route takes a place id and nothing else (a query
  string is refused, 400), the words are built on the server from the catalogue the learner may
  see (`placeText` → `campusTour` → `placeSpeech`), the key is read only where the voice is made,
  the ElevenLabs URL is a constant with a validated voice id (no SSRF), and the audio is cached by
  a hash of voice, model and words, so each place is paid for once.
- **The look is ids only.** zod enums on the API, shape CHECKs in the database, unknown keys
  stripped (no mass assignment: `photoKey` can't be set through `PATCH /api/me`), CSRF through
  `requireReady`.
- **The photo is handled well.** Size from `content-length` before the body is read, magic bytes
  before decoding, a pixel limit, the crop checked twice, every byte re-encoded, metadata dropped,
  served `private, no-store` with `nosniff` and `same-origin`, the key never leaves the server, the
  switch refused in production and on staging, the file deleted with the account and exported.

The problems are all in the **staging site** and the guard around it:

1. **A8-06 / A11-28 (High).** A staging site is a public website whose `/dev/outbox` shows every
   phone number typed and every sign-in PIN and guardian link, to anyone, with no sign-in. Anyone
   can sign in as anyone and approve any "guardian" consent. Real people's numbers and documents
   can land there, abroad.
2. **A8-07 / A11-29 (High).** The staging guard refuses `UF_PROVIDERS=live` but not the pieces
   live mode is made of: `DATABASE_URL` (any Postgres, including production's), `ANTHROPIC_API_KEY`,
   `ELEVENLABS_API_KEY`. One copied variable points a public site with an open outbox at the
   production database.
3. **A8-08 (Medium).** `UF_LOCAL_PRODUCTION_BUILD=1` on Render (or any host that isn't Vercel)
   turns production off entirely, and with it the new Render refusal and the S3 region check.

## 7. What's genuinely good

- Read aloud's design removes the risk rather than filtering it: the client can't send text at all, so there is nothing to sanitise.
- The photo path checks the same things at every layer (route, documents, database CHECK), and re-encodes rather than trusting any byte of the original.
- `DELETE /api/me` finds the photo key as the owner, so a learner whose consent was withdrawn still loses the file with the account.
- The health route was written to say nothing, and its test holds it to that.
- Production on Render refuses to start with an explicit reason, and the staging rules have tests; the gaps above are in what the rules cover, not in how they are enforced.
