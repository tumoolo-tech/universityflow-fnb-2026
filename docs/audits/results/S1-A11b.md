## Executive summary

What this session built for learners is privacy-minded:

- **The look is ids only**, chosen from fixed lists, held to id shapes in the database, exported
  with the profile and deleted with it. It never reaches the AI (agent-context.ts:61-67 reads the
  display name, grade, school-finished flag and goal only) and is logged only as the fixed audit
  word `profile.updated`.
- **The photo is off in production and on staging** (config.ts:446-451), consent-gated per request,
  stored only after a server crop to 512 × 512 black and white with **all metadata (GPS included)
  dropped**, never sent to the AI, exported as the image itself (whether or not the switch is on),
  and deleted with the account (store.ts:3193-3214). It stays in South Africa (the files service).
- **ElevenLabs receives no personal information.** Only catalogue text, built on the server from a
  place id, from our server's IP, with no learner identifier.
- **The privacy page names every operator the code uses today**, marks every value only the owner
  can give, and says plainly what crosses the border.

The findings:

1. **Staging (A11-28, A11-29, High, joint with A8-06, A8-07).** A staging site on Render
   (Frankfurt) has no access gate and publishes every number typed, with its PIN, on `/dev/outbox`;
   and its guard doesn't stop it being pointed at the production database or the real AI. The
   "synthetic data only" rule is a banner and a YAML file, not something the code enforces.
2. **ElevenLabs is on for minors whenever a key is set (A11-30, Medium).** The privacy page says
   Read aloud "stays off for learners until ElevenLabs gives its written approval"; no code does
   that. The only control is a line in status.md: "no key on the live server until then".
3. **The photo's consent is a server switch, not a data-layer rule (A11-31, Medium).** When v4
   arrives and the switch goes on, learners whose guardian agreed to v3 can add a photo. A11-13's
   fix (migration 0021) is the pattern to follow.
4. **Smaller:** "Remove photo" is refused once consent lapses (A11-32); the look isn't named on the
   privacy page or the store page (A11-33); the privacy page still lists plan maps as "coming
   later" though their template, ticks and target months are collected now (A11-34).

**My plan maps are sound on privacy.** The learner's own words are refused in production twice
(the store and a database trigger) until consent wording names them; the crisis check on what
they write keeps nothing; maps are exported verbatim, deleted with the account, behind RLS and
the consent gate, and never reach the AI.

## What's genuinely good

- **GPS and every other piece of metadata is gone from a photo before it is kept**, and the server
  re-encodes rather than trusting the upload. The black-and-white 512-pixel square keeps only what
  the card shows.
- **The photo switch was refused on staging too** (922f59b), the day staging was built: someone
  thought about where a production build might run.
- **The export carries the photo whatever the switch**: what is held is given back.
- **ElevenLabs gets nothing it could tie to a learner**, by design (a place id in, catalogue text
  out, our server as the caller), and the privacy page explains it in a sentence a 15-year-old can
  read.
- **Plan maps keep a minor's own words out of production in two places**, the store and a
  database trigger, and the crisis check reads what they write without keeping any of it.
- **The privacy page refuses to guess**: every value only the owner can give is marked "Owner to
  fill", and a test keeps the page and the store document naming the same operators.
