UniversityFlow is a pnpm/Turborepo monorepo: `apps/web` (Next.js 16), `apps/native` (Expo SDK 57)
and `packages/*`. Read `CLAUDE.md` (the 11 hard rules and the version pins) and `status.md`
(the 14 gotchas) before grading anything.

**Grade these as this project's own rules, not as style preferences:**

1. `packages/*` never import from `apps/*`.
2. Admission facts (requirements, deadlines, fees, score formulas) appear **only** in
   `packages/catalogue` and `packages/admissions`. One in a prompt, a component or a content
   string is **High**: a wrong requirement costs a learner a year.
3. Catalogue records carry `sourceUrl`, `academicYear`, `verifiedOn`, `verifiedBy`; a draft
   reaching a learner is **Critical**. Check `catalogueView` and every caller.
4. No personal information in logs, job payloads, analytics, snapshots or fixtures.
5. Nothing about a minor is processed before guardian consent, **enforced in the data layer**
   (`packages/db`), not only on a screen.
6. Every value read from a document is confirmed by the student before a calculation uses it.
7. The crisis red-team (`packages/evals`) passes 100%.
8. Strings from `packages/content`; design values from `packages/tokens`.
11. `admissions`, `catalogue`, `planner`, `content`, `tokens`, `ui` never touch DOM or Node
    globals; `apps/native` lists every workspace package it reaches.

**Load-bearing places:** `apps/web/lib/server/services.ts` (provider wiring; production must
refuse every stand-in), `packages/agent/src/crisis.ts` and `runner.ts` (crisis answers before
any model call), `packages/db/src/store.ts` (consent gate, RLS, sign-in limits).

**Agent-written code.** Much of this repo is written with coding agents. Look specifically for
what they get wrong: tests that assert the mock instead of the behaviour, a stand-in quietly
used in a production path, a guard weakened to make a check pass, a TODO standing in for a
requirement, and comments that describe intent the code doesn't implement.
